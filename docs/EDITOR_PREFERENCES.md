# Editor and external comparison preferences

Editor settings are stored under `editor.*`. Comparison windows and diff panes observe them via AppStorage, including windows already open. Editor font, tab spacing and display decorations update on existing NSTextViews without replacing their strings, draft state or undo managers. Line number, wrapping and scroll synchronization share the same persisted defaults as Preferences. New comparison windows initialize their local layout choice from `editor.comparisonLayoutMode`, whose new default is automatic and is independent of the legacy three-column preference. Toolbar layout changes apply only to that window; automatic layout reevaluates file status after save/stage without replacing the working draft. Only the working-tree result is editable; revision reference columns are read-only.

The native editable comparison surface supports current-line shading and invisible-character drawing through AppKit. Syntax and character-difference switches affect both editable comparison and read-only patch views. Added, deleted and modified colors have RGB overrides. Empty overrides use semantic system green/red/orange so the initial defaults adapt to appearance; Reset colors restores these semantic defaults. Editable comparison classifies pure insertions/deletions and replacements by diff block ranges. Patch views retain separate addition/deletion colors. Font fallback is the system monospace font when a saved font is unavailable. Sizes clamp to 9–32 and tab widths to 1–16.

External tool preferences retain the existing `externalComparisonExecutable` and `externalComparisonArguments` keys. Fields are drafts until Validate and Apply succeeds; invalid JSON does not overwrite the active configuration. Arguments are JSON arrays, with one element per argv entry and no shell parsing. `ExternalDiffArguments` restricts placeholders to `{left}`, `{right}`, `{base}`, and `{result}`. Existing comparison actions also open this same preferences form.

Tools receive temporary read-only revision copies and a writable temporary result. Successful result output becomes a pending comparison result, requiring confirmation before it replaces the editor draft; saving still performs the existing expected-content checks. Selecting a template does not directly modify repository files.

Validation performed for this change: Swift syntax parsing of edited views; four localization tables passed plutil; git diff whitespace validation. Native build and runtime acceptance are handled separately by the integrating task.
