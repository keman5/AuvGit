# Embedded project terminal

Press **Command + backtick (`)** in a project window, or click the terminal icon in the status bar. The terminal opens below the project with a draggable split divider and receives keyboard focus. Press the shortcut again to hide it; opening it again restores the same running shell and scrollback. The activity log has its own adjacent list icon.

Each project window owns up to eight sessions, keyed by the repository's canonical path. Switching repositories changes the attached terminal view and preserves the previous repository's session. Keystrokes are checked against the currently selected repository before reaching the PTY, including while SwiftUI is switching views. The initial working directory is passed directly to `forkpty`/`exec`, so spaces and shell metacharacters in paths are never interpolated into commands. The account's configured shell starts as an interactive login shell; its normal startup files and environment apply. A user's startup file may change its own working directory.

The terminal is the official [SwiftTerm](https://github.com/migueldeicaza/SwiftTerm) `LocalProcessTerminalView`, pinned to version **1.20.0**. It provides PTY input/output, ANSI colors, cursor movement, alternate screens, scrollback, clipboard integration, Control-C and terminal resize. Repository switching does not issue a `cd` to an existing session: manual directory changes remain part of that repository's shell.

The down-chevron hides the panel without stopping jobs. The X closes its session and stops the shell and current descendants; the session menu can close hidden sessions. Closing a repository tab also closes that repository's terminal in the window. At the session limit, no existing job is silently evicted: close a session from the menu, then press Start Terminal. After the shell exits, its output remains visible and Restart Shell starts a fresh session at the repository root.

Closing the window releases its sessions. Application termination synchronously signals the owned shell/descendants, including the foreground process group, before the application exits. Normal session closure allows a short grace period before escalation. Cleanup checks Darwin kernel process start times before each signal so PID reuse is not treated as ownership. This covers terminal-owned processes present at cleanup; intentionally detached daemons that have reparented and left the terminal's process groups have their own lifecycle.

The shortcut monitor belongs only to the project window, ignores attached sheets and does not intercept settings or comparison windows. It consumes Command + backtick before macOS window cycling. Shift, Option and Control combinations retain their normal behavior. Language changes rebuild localized window content below `MainWindow` while retaining its session owner and running shells.

The panel has a 210-point minimum height and a preferred height of 280 points, with a draggable divider. The terminal is labelled as an accessibility text area so VoiceOver can locate it. SwiftTerm 1.20's macOS accessibility service is a stub and its `screenReaderMode` option has no active implementation; reading terminal text through VoiceOver remains an upstream limitation. RayGit does not add rich-text accessibility probing.

When the terminal is open, workspace panes use smaller minimum heights and the commit form scrolls instead of forcing its full intrinsic height onto the nested split view. This keeps the project selectors inside their own visible pane. Hiding the terminal restores the normal workspace height preferences.

`scripts/build-app.sh` uses the native SwiftPM build system and copies both the SwiftTerm Metal resource bundle and `Resources/THIRD_PARTY_NOTICES.txt` into `Contents/Resources` of the distributable app. SwiftTerm 1.20 probes that location directly and compiles `Shaders.metal` at runtime when no precompiled Metal library is supplied, without relying on the developer's absolute build directory. The notices contain SwiftTerm's complete MIT license and original copyright notices.

Focused automated checks: `swift test --build-system native --filter TerminalTests` covers direct cwd handling with spaces, true tty stdin/stdout, interactive input, foreground Control-C, shell exit and descendant cleanup. Localization parity is covered by `swift test --build-system native --filter LocalizationTests`. Additional manual coverage can check ANSI/alternate-screen programs, clipboard and resizing beyond the verified initial terminal dimensions.

Manual checks completed in the packaged app: Command + backtick opens and focuses the terminal; `pwd` starts at the selected repository; hide/reopen preserves a shell environment variable; Control-C interrupts `sleep` and the shell accepts the next command; two repositories keep isolated environment variables and working directories; app quit cleans up the old shell and reopening starts a new one; full commit drafts and repository tabs restore. After the panel-height adjustment, `stty size` reports 11 rows.

The latest release screenshot confirms that opening the terminal leaves the project controls inside their panes without overlap. File, diff and history panes scroll independently, and the commit form scrolls. Changing the language immediately updates the terminal labels to Chinese while preserving the running shell's environment; the terminal-written `terminal-language-proof.txt` containing `|language` provides the session-preservation evidence.
