# 文件比较器、部分暂存与网络任务

2026-10-03 实现。比较器使用完整文件版本与独立原生文本编辑器；历史和 stash 对比保持只读。

## 入口与布局

- 双击工作区文件、右键“文件比较”，或点击差异栏“编辑／三栏对比”，打开独立比较器。
- 默认按文件状态自动布局：仅未暂存／未跟踪为索引→工作区双栏，仅已暂存为 HEAD→工作区双栏；同时有已暂存与未暂存改动时为 HEAD／工作区结果／索引三栏。每窗口可手动选双栏、三栏或补丁，不会改变其他窗口的选择。编辑器偏好可显式设置新窗口的默认模式，旧三栏偏好不影响新的自动默认。
- 冲突文件默认三栏：Ours（HEAD，index stage 2）／现有工作区合并结果／Theirs（index stage 3）；左栏可手动切为共同祖先。打开文件保留工作区原文及已有冲突标记，不自动运行合并或覆盖草稿。
- 图片版本存在时可从 HEAD／索引／工作区／base／ours／theirs 中选择任意两个有图片的版本并排或透明叠加。PNG/JPEG 等由 NSImage 解码，显示尺寸和字节数。
- 大文本（超过 2 MB、最多 32 MB）自动进入只读分页。每页最多 500 行，单个超长行仍按最多 100,000 UTF-16 单元分段，避免一次排版全部内容。分页沿用自动或手动双／三栏版本顺序，全部只读。
- 超过 32 MB 的工作区或历史 UTF-8 文件进入真正流式只读查看：FileHandle 每页只读约 128 KB、最多 500 行，超长行按字节边界分段，UTF-8 多字节字符不截断。工作区以文件大小、修改时间和 inode 验证快照，发现外部修改要求重新加载。历史 HEAD／索引／base／ours／theirs 先按不可变 blob OID 直接导出受控临时文件，stdout 不进入 32 MB 内存捕获；版本选择器可切换版本。取消／失败清理部分导出，释放 reader 清理完整临时文件。
- 补丁页提供按行、按块暂存／取消暂存；操作前必须保存草稿。普通新增和删除文件也支持选行：仅更新索引，保留工作区原始内容／删除状态；无末尾换行的文本保留对应标记。已暂存重命名的目标可按行暂存后续内容修改，重命名本身留在索引中。已暂存重命名支持只取消所选内容行，原路径删除与新路径身份仍留在索引。对于 Git status 常见的 D 旧路径＋?? 新路径，在新文件比较器“更多→建立重命名关系…”选择缺失的受跟踪原路径：以原索引内容建立新索引路径并移除旧条目，不更改工作区，然后逐行暂存需要的内容。
- 选择内容行不暂存未选择的可执行权限变更。CRLF 补丁保留原始字节。操作前重新校验 HEAD／索引／工作区内容，发现外部变化要求重新加载。新增空文件或仅权限修改没有内容块，使用整文件操作。

## 编辑、接受与合并

- 原生 NSTextView 编辑、复制粘贴、撤销重做；独立行号边栏不进入保存内容或代码复制。
- 双栏／三栏切换复用文本视图，保留草稿、光标和撤销历史。高亮使用临时属性，不修改文本和撤销记录。
- 在可编辑栏的修改块上右键，选择“接受此块：某版本”，将该版本的对应块应用到当前编辑草稿。插入／删除块也支持接受；末尾删除可在前一行使用菜单。
- “采用完整版本”替换内存工作区草稿，仍需显式保存。
- 只有工作区／结果栏可编辑；三栏结果位于中间。HEAD、索引、Ours、Theirs、Base 参考栏全部只读。保存草稿只写工作区；“保存并暂存”、部分暂存和标记解决仍是明确的独立操作。
- 冲突的“自动合并”使用 `git merge-file -p --diff3` 对临时副本合并，只返回草稿。没有修改真实工作区或索引。冲突会保留明确的 ours／base／theirs 标记，用户编辑并保存后再标记解决。
- 重新加载、关闭窗口、退出应用时保护未保存草稿。保存失败保留草稿。保存前比较精确字节，检测外部文件修改。
- UTF-8、UTF-8 BOM、UTF-16 LE／BE BOM 都可编辑；保存保留原编码、BOM、统一 LF／CRLF／CR 和权限。更多菜单提供显式解码选择、编码转换与换行规范化，未保存草稿须先保存；无法以所选编码无损表示的字符会拒绝写入。Latin-1 通过显式会话解码可查看、转换、保存并继续编辑，不作自动猜测。
- 二进制、未明确解码的未知编码、未规范化的混合换行、符号链接、非普通文件、只读文件、超过 2 MB 文本不能编辑；不会沿符号链接写仓库外路径。

- 已删除文件可在“更多→恢复版本”选择索引或历史版本重建，保留来源可执行权限。modify/delete 冲突可恢复选定版本并解决，也可确认“以删除解决冲突”。操作校验 HEAD、各冲突 stage 的存在状态、模式、OID 和精确字节；外部修改或符号链接替换会拒绝操作。

## 浏览与外部比较

- 可拖动分栏、显示行号、自动换行、同步滚动、搜索高亮、匹配和修改块跳转。
- 修改行配对后提供字符级差异，UTF-16 范围保持完整 Unicode 字符；超出详细算法阈值时保守标记变化区。
- Swift、JS/TS、Go、Python、JSON、shell、C/C++、Rust 基础词法高亮支持关键词、字符串、注释和数字。补丁并排视图同样显示字符差异与基础高亮。
- “外部比较”菜单可选择左右版本（含冲突阶段），选择工具后保存工具路径，后续直接启动。通过参数数组传递临时只读副本，不经过 shell，不写仓库文件。兼容可执行文件／应用 bundle。提供持久化 JSON 参数数组模板，每个字符串为独立 argv 参数，支持 {left}／{right}／{base}／{result} 占位符；没有 shell 分词或展开。输入副本只读，result 是受控目录中的可写临时副本；成功结果先保留待应用，用户确认“将外部结果应用到草稿”后才替换编辑草稿。运行期间新增草稿或磁盘变化不会被自动覆盖；显式保存仍执行原始字节校验。
- 简体中文、繁體中文、English、日本語提供新界面文案。

## 网络任务与凭据

- 网络面板支持 fetch、仅快进 pull、push dry-run 预览和确认后实际推送。进度来自 Git stderr 的真实阶段／百分比，未报告百分比时显示阶段文本。
- push 预览绑定仓库路径、引用与分支／远程／push 配置摘要；执行前状态变化会要求重新预览。远端在预览后仍可能改变，Git 的最终推送结果才是成功依据。
- 取消会传递到真实 Git 子进程组，先 TERM 后 KILL；超时保留 120 秒默认。进程组在 spawn 时设置，使用 close-on-exec 防止并发任务互留管道，信号完成后才回收 leader 以避免 PID 复用。
- 显示已配置凭据助手的安全名称；自定义助手内容可能含秘密，仅显示通用标签。可确认将当前仓库本地助手设为 osxkeychain；不读取密码或令牌。
- SSH 使用用户已有配置和 agent；已有 GIT_SSH_COMMAND 保留。未配置时采用 BatchMode，交互凭据提示关闭。GUI PATH 补充标准 Homebrew 目录，缺 Git LFS 时给出可操作提示，不自动安装。

## 验证与边界

`AdvancedDiffTests` 的 10 项测试已通过，覆盖逐块接受、重复／移动行穷举重构、Unicode 字符范围、词法范围、UTF-16、分页和干净／冲突三方合并。`GitProcessTests` 的 6 项测试已通过，覆盖取消后真正终止 TERM-resistant 子进程、已取消任务不启动、超时与真实 stderr 进度、并发管道隔离、凭据助手不泄露、push dry-run 不改临时裸仓库及真实推送更新引用。最新完整验证已由主代理运行：67项GitCore与4项本地化，共71项通过；当前原生界面验证见 [VALIDATION.md](VALIDATION.md)。新增 `StreamingComparisonTests` 覆盖超过 32 MB 的按块读取、跨页 UTF-8／超长行、BOM／行分页、外部修改及符号链接拒绝；另包含 33 MB HEAD／索引流式导出、索引更新不改变已导出快照、取消清理及不覆盖现有导出文件；这些测试已包含在上述71项完整验证中并通过。

可交互验收仓库：`python3 scripts/make-compare-demo.py`。包含三个版本各异的 Editor.swift 和真实 Conflict.txt，不关联生产远端。

明确限制：超过 32 MB 的历史 blob 已提供流式导出和分页，但完整导出仍需要等量临时磁盘空间；磁盘写入失败由 Git 错误报告并清理。2–32 MB 分页仍是内存快照的限量排版；超过 32 MB 工作区是按需 FileHandle 读取。超大 UTF-16、未知编码和二进制需要外部查看器。同步滚动按锚点插值，自动换行时不保证像素级对齐。基础词法高亮不等同编译器解析（补丁跨行注释可能不连续）。未知编码必须先显式选择可无损解码方式，含 NUL 的二进制不会转为文本。部分暂存依赖 Git 文本补丁；UTF-16 可完整暂存或显式转换 UTF-8 后逐行操作。保存检查不是跨进程文件锁。真实远程服务认证和用户选定外部比较工具还需用户环境验收；本地裸仓库测试不能代替远程验收。

本轮比较器补齐：`ComparisonExtrasTests` 的初版 7 项定向测试通过，覆盖 UTF-16 双端序保存、Latin-1 转换后继续编辑、重命名身份保留与部分内容操作、删除 executable 恢复、HEAD／符号链接变化防护、modify/delete 双向解决与安全参数模板。后续增强混合 CR/LF 与不可表示字符拒绝写入保护，需由主代理最终全集重新确认。旧测试中的 UTF-16 只读断言已根据新可编辑行为更新，二进制及非法编码保护仍保留。

本轮状态自动布局与参考栏只读改动尚待主代理统一构建及原生界面验收；媒体和超大文件流式查看保留专用版本选择器，不套用可编辑文本布局。

## 2026-10-03 冲突选择与差异视觉补齐

本轮实际参考 SmartGit 26.1 的 Conflict Solver，补齐全文件 Ours／Theirs／Base 采用入口，以及每个冲突块的“采用 Ours”“采用 Theirs”“先 Ours 再 Theirs”“先 Theirs 再 Ours”。按顺序保留双方会依所选顺序拼接块内内容；操作只替换内存草稿，保留其他冲突块，支持原生撤销，保存和暂存仍为显式动作。用完整版本替换已有未保存草稿时提供确认，取消保留当前草稿。

比较编辑器行号比代码小 2pt（最低 8pt），使用随深浅外观变化的轻灰，并保持代码基线对齐。改动行与字符采用两级底色：行级浅色 alpha 0.22／深色 0.28，字符级浅色 0.43／深色 0.48；新增绿、删除红、修改橙，沿用用户自定义颜色。工作区中完整解析出的未解决冲突块，从起始标记到结束标记统一使用删除色红底，块内字符差异仍保持更强对比。补丁视图只弱化行号列属性，保留原文和字符偏移；完整文件编辑器行号仍位于独立边栏。

本轮 `ConflictDraftTests` 4 项 native 测试通过，四语言／21 表／860 键检查和本机 Release 构建通过。真实 diff3 临时仓库已验证全文件选择、逐块按序保留双方、撤销及替换确认取消，且测试后磁盘与索引仍保持原始未解决冲突；详见 [VALIDATION.md](VALIDATION.md) 本轮记录。浅色界面已实际检查，深色样式与切换刷新已实现，但本轮尚未通过系统外观切换完成深色原生视觉验收。
